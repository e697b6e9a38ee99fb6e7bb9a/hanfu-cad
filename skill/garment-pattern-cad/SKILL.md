# 实物服装逆向打版 + CAD 出图

## 何时用

- 用户给一张成衣图/文物形制图/手绘裁片稿，要出裁片图或下厂纸样
- 要按尺码推档（一个版 → 一档码）
- 要把裁片导出成 CAD 能开的 DXF（顺序：先 SVG、过叠合，再导 DXF，见 §4.5）
- 汉服/传统服饰形制复原（术语与结构另有陷阱，见 §1）

对穿交这件形制的具体结论沉淀在文末 §9，可直接引用。

---

## §0 四条铁律（顺序不能换）

1. **闸门式推进**：先交付规划 → 审核通过 → 才动手。跳步必返工。
2. **术语先锚定，再画第一笔**。定义错了，后面每一张图都是废的，而且错得"很专业"——最难自查。
3. **每一步都要有可复核的证据**，不接受"我觉得像"。证据形态：量纲锚点、IoU、断言数。
4. **先 SVG，后 CAD**。SVG 是主产物，DXF 是派生物；SVG 没过 §4 叠合闸门，不许导 DXF。

---

## §1 术语锚定（最容易全案报废的一步）

民间叫法与文物定名经常是两回事，而 LLM 的先验极容易把它归到"最像的那一类"。

**做法**：
- 拿用户给的词去搜**权威文本**（博物馆修复报告、专著章节、作者文集），不要搜科普段子
- 找到**一句话定义**，写成 `A = B 的剪裁 + C 的穿法` 这种可判真假的句式
- 用这一定义回测已有资料，凡是"按新定义不成立"的旧判据**整表作废**，不要修补

**实例（本项目踩过的坑）**：
> ❌ 初判"对穿交 = 全交领对称续衽"（把交领直接裁出来）
> ✅ 正解"对穿交 = **直领对襟的剪裁 + 交领的穿法**"，属二次成型：平铺两襟基本平行、少量交叠；上身后两襟内收才成交领状。
> 依据：孙韬《孙韬文集》4.3「直领对穿交衣裳的上身形态」/ 4.4「裁片改变和斜裁」；汉服颂《科普汉服领襟分类》"对穿交问题"一节。
> 判据：平铺图上两襟是否平行 —— 这一条就能证伪错误定义。

**写进交付物的形式**：一张「形制核对表」，每行 = 一个可观察特征 + 实物证据 + 本版取值 + 判定。特征错一条就是形制错。

## §2 量纲锚定（决定整套数字可信度）

优先级从高到低，**不许跳级**：

1. 图纸上的**尺寸标注**（最硬）
2. 图纸**网格**
3. 图内**已知物**（纽扣直径、纹样单元、模特身高）
4. **人体比例**推算（最软）

没有任何锚点时，明确标 `UNSCALED`，不要假装有比例。

**实操**：
- 定出 `mm/px`（本项目正视 3.89、背视 4.04）
- 立刻做一次**各向异性检验**：横向用已知长度（如通袖）锁 `sx`，纵向让 IoU 自动拟合出 `sy`。两者相差 ≤2% 才说明图纸是等比的、你的比例没错。>2% 说明模型被拉伸了，先修模型再谈吻合度。
- 记下所有原始标注（本项目：通袖 218 / 衣长 82.5 / 摆宽 125 / 单边 76 / 交叠 23 / 三角高 17·14 / 袖口 6·13），**保留原单位与原文写法**，换算写在旁边。

**"围"与"净平"必须分开**：标注"袖口 13"指的是**围 130**，净平开口只有 65。这一处差 2 倍，且不会报错，只会做出一件穿不进去的衣服。

## §3 裁片几何：曲线规范（"棱角分明"的根因）

**症状**：用户说"太棱角分明、曲线不平滑"。
**根因**：用 `("L", pt)` 折线 6~10 段去近似一段弧。

**错误解法**：全局 Catmull-Rom 平滑 → 角落鼓出、包围盒暴涨（本项目后片从 728×946 涨到整幅画布）。
**正确解法**：分而治之。

| 部位 | 处理 |
|---|---|
| 直线段（侧缝、后中、下摆水平段） | 保持真直线 |
| 曲率明确段（袖窿底、底摆起翘、领弧） | **三次贝塞尔**，控制柄由端点切线方向 × 长度系数定 |
| 两段相接处 | **G1 三次混合圆角**：取两段各自切线，按恒定比例 k 混合出中间三次段（本项目 k=0.92，腋下 R=70） |
| 需要精确切分 | **de Casteljau**，不要采样近似 |

**关键工程细节**：新增一种曲线命令（如 `Q`）时，必须同步改**三处**：
1. `path_d()` / SVG 序列化
2. `flat()` 采样（用于 bbox 与面积）
3. 校验器的采样函数

漏一处 = 曲线静默丢失：bbox 变小、圆角没画出来、但程序不报错。判据：改完立刻看 bbox 与预览图对不上就是漏了。

## §4 像素级叠合闸门（本项目最有价值的一环）

只做"尺寸自洽"是不够的——参数全对也能拼出一件不像的衣服。必须和官图**逐像素比**。

### 方法（`verification/overlay.py`）

1. **官图取实心掩膜**：二值化 → 笔画**膨胀 3px 闭合 JPEG 断口** → 自四边洪泛求外部背景 → 取反 → **腐蚀还原** → 取最大连通域。
   （因为形制图是线稿不是色块，直接取轮廓会得到空心轮廓而非成衣）
2. **模型侧栅格化**：把裁片按**真实拼合关系**摆（后片中缝对拼、前片两片交叠 N mm、领缘竖起、接袖接于 X），不要各片单独比。
3. **配准**：横向由已知长度（通袖）锁定 `sx`；`sy` + 平移 `cx/y0` 用 **IoU 最大化网格搜索**（本项目 21×15×5 组）。先拟合再评判，避免用错标定冤枉版型。
4. **指标**：IoU、Precision（模型多画的）、Recall（官图有而模型漏的），外加**逐列上下轮廓偏差**定位残差落在哪。

### 判定口径

| IoU | 结论 |
|---|---|
| ≥0.90 | 优 |
| 0.85–0.90 | 合格，但**必须在报告里逐条说明残差** |
| <0.85 | 不通过 |

本项目终值：正视 0.8717 / 背视 0.8925（优化前 0.6855）。

### 残差分析要做**敏感度测试**

别急着改参数。本项目残差里"下摆两角外扩"看着最显眼，但实测摆宽 1250→1000 只让 IoU +0.5% —— **它不是主因**。主因是袖上缘偏高 20mm（0.8° 的下垂角）和后领高度差 25mm。

真因往往藏在"看起来不显眼"的地方：**用面积排序，不用视觉醒目度排序。**

## §4.5 SVG 逆向成型（必须在 CAD 之前）

**顺序不能反：实物/官图 → 逆向 → SVG 裁片图 → §4 叠合闸门 → CAD/DXF。**

SVG 是"可审的主产物"，DXF 是"可下厂的派生物"。理由：

- SVG 能直接叠合官图、看曲线、看真实拼合关系；DXF 在 CAD 里只能看线，做不了像素级验证；
- 逆向阶段改的是轮廓，SVG 改一次、预览一次、叠合一次，反馈回路最短；
- DXF 一旦成为主产物，尺寸/图层/刀口会分叉，最后没人知道哪份是准的。

**做法**：

1. `build.py` 只算几何，先输出 `pieces.json` + `preview.svg`（或单码 SVG）；
2. SVG 必须能按真实拼合关系摆片（后中对拼、前片交叠、领缘竖起），直接喂给 §4 的叠合；
3. §4 叠合与尺寸断言都通过，才允许 `export_dxf.py` 从**同一份** `pieces.json` 导 DXF；
4. 三件套同源：`.svg` / `.dxf` / `.pieces.json` 必须来自同一次 build，禁止手改其中一份；
5. 出 DXF 后做一次**跨格式对账**：逐片 bbox、闭合性、刀口数、图层数，SVG vs DXF 差 ≤0.1mm / 0 项。

**信息量只许降、不许反向约束**：本项目 SVG 有 `SEAM` 层，DXF 只有 5 层。派生时可以做有损映射，但不能用 DXF 的低信息量去删 SVG 的层；下游要缝线，就在 DXF 补 `SEW_线迹`，而不是从 SVG 删 `SEAM`。

**中间产物**：逆向的二值图、裁切块、局部放大留在 `reverse/`；成型产物是 SVG，不是 DXF。

**判据**：SVG 还没过 §4，就不要讨论 DXF 的图层和字体——那是在给一个没定的版做包装。

## §5 尺码推档

- 档差：**GB/T 1335.1（男）/ 1335.2（女）**，身高 5cm / 胸围 4cm 一档
- 中间体：女 160/84A、男 170/88A
- 放量另设档：紧身 / 合体 / 宽松，作为系数而非绝对值

### 资料置信度口径（比数据本身更重要）

> **同一篇文章被多个站点转载，只算 1 个独立来源。**

本项目实测：所谓"女装放量 4–6/8–10/≥14"来自 2012 年一篇裁剪班讲义，被 4 个站转载 → 独立来源数 = **1**，置信度低。后来用户提供**厂商实物出货尺码表**，一票否决上述所有网络资料，定为最高置信度基准。

**结论**：网络汉服放量资料普遍是单一来源的自我繁殖，**不可作为定版依据**；能拿到厂商实物表/博物馆实测就用那个。

### 两套基准并存是对的

女装用文物复原版（保留形制），男装用厂商表（保证可穿）。`--profile` 不填时按性别自动选，避免用户记参数。

### 推档时的硬编码陷阱

图纸上的文字标注（"后中长 825"）换码后不会自动变，必须改成格式化字符串。**任何写死数字的文案都是 bug**，只是不报错。

## §6 CAD 出图（ezdxf，从已过闸的 SVG/JSON 派生）

**前置条件**：§4.5 的 SVG 已过叠合与尺寸闸门。CAD 不是第一现场；`export_dxf.py` 只做序列化，不在 CAD 里手动补线。

```python
doc = ezdxf.new("R2010", setup=True)
doc.units = ezdxf.units.MM          # INSUNITS=4
```

- **图层分离**，别全塞 0 层：`CUT_轮廓` / `GRAIN_布纹` / `NOTCH_刀口` / `TEXT_文字` / `DIM_标注`
- **中文必乱码除非显式建样式**：默认 `Standard` 走 `txt.shx`，没有汉字字形 →
  ```python
  doc.styles.add("CN", font="simsun.ttc")
  msp.add_text("前片 ×2", height=35, dxfattribs={"layer": TEXT, "style": "CN"})
  ```
  验收：`doc.audit() == 0` 且所有 TEXT 的 `dt.dxf.style == "CN"`
- 布纹线画正规 V 形箭头（沿方向后退 30、沿法向 ±12），不要一根光杆
- 每个码一套三件：`.dxf` + `.svg` + `.pieces.json`（几何侧车，供二次开发）
- **侧车 JSON 是解耦的关键**：`build.py` 只算几何 → `pieces.json` → `export_dxf.py` 只做转换。改出图格式不用碰版型代码。
- **单向数据流**：`build.py → SVG + pieces.json →（过闸）→ export_dxf.py → DXF`。禁止从 DXF 回改 SVG，也禁止两份各改一次。

## §7 交付前自检

写成断言，别靠眼睛：

```
verification/verify.py → 28 项全 PASS
```

要点：
- **期望值从生成器反读**（`import build`），不要在两处各写一遍数字 —— 否则改了版型断言还是绿的
- 断言的粒度：画布单位、viewBox 与 mm 1:1、图层齐备、片数、每片关键尺寸、刀口位置、曲线命令数
- **SVG→DXF 跨格式对账**：三件套同源同一次 build；逐片 bbox、闭合性、刀口数、图层数一致（≤0.1mm / 0 项），否则先修导出，不要修版型
- 报 `FAILS: 0` 之外还要打印一句人话结论，方便贴给用户

## §8 坑清单（都是实测踩过的）

| 坑 | 症状 | 解 |
|---|---|---|
| 折线近似曲线 | 用户："太棱角分明" | 三次贝塞尔 + G1 混合，见 §3 |
| 新增命令漏同步三处 | 圆角静默消失、bbox 变小 | §3 的三处清单 |
| 袖口"围"当"净平" | 差 2 倍，做出来穿不进 | §2 末 |
| 小码越界 | 某码崩溃 `_T_ is None` | 分界点取 `min(硬编码, 实际值)`，并给 `or 1.0` 兜底 |
| 硬编码文案 | 换码后标注不跟着变 | 改格式化字符串 |
| 中文 DXF 乱码 | 打开全是 `?` | `doc.styles.add("CN", font="simsun.ttc")` |
| 用错标定评判版型 | 冤枉了一个好版 | 先 IoU 拟合平移/纵向缩放，再下结论 |
| 按视觉醒目度排残差 | 改错参数 | 按面积排，配敏感度测试 |
| 误解用户一句"去掉袖片" | 连做三版全废 | **回上一个存档点，只加最小补丁**；有歧义先问，别"想" |
| 反推顺序错 | 存档点丢失 | 每个过审版立刻 `archive/vN_说明/` 完整留档（含 build.py + 图 + 核对表） |
| 跳过 SVG 直接出 DXF | CAD 能开，但无法叠合/审图；改版后 SVG 与 DXF 分叉 | 先出 SVG 过 §4，再从同一份 pieces.json 导 DXF；跨格式对账 |

## §9 对穿交（本项目沉淀的形制结论，可直接引用）

- **定义**：对穿交 = 直领对襟的剪裁 + 交领的穿法（二次成型），非"把交领裁出来"
- **实物基准**：无锡七房桥钱樟夫妇墓 · 鸟衔花枝纹缎夹袄（明中后期，无锡博物院，中国丝绸博物馆 2014–2018 修复）
- **实测**：通袖 218 / 衣长 82.5 / 平铺摆宽 125 / 单边 76 / 交叠 23 / 内镶三角高 17·14 / 后中缝贯通 / 单层无衬里 / 袖背拼缝处做斜省（两袖端略下垂，非水平）/ 系带在前襟不在身侧
- **原件左衽**。**改右衽不改变裁片**——两襟同形镜像，右衽只决定穿着时哪片在外。这是被反复问到的点。
- **半臂化**：去掉独立袖片即可，袖底斜下并入侧缝，袖口为短竖边。不要把"去袖片"理解成"通袖一片"（本项目为此废过一整条分支）。
- **通袖不是跨版型的可比指标**：厂商版 163 与我方 165 看似接近，但袖长 53 vs 26.5 —— 半臂与长袖的通袖本来就不该对等。

## §10 目录骨架（照这个铺即可）

```
PLAN.md               规划 + 形制论证（版本化，v2.0 才作数）
pattern/              build.py（几何）/ sizing.py（推档）/ export_dxf.py / make.py（CLI）
verification/         overlay.py（叠合）/ fit.py（拟合）/ verify.py（断言）/ report.py
sources/              原始资料 + manifest.csv（平台/网址/类型/是否有量纲/置信度/备注）
archive/              每个过审存档点一个目录，含当版 build.py
out/                  <profile>_<性别>_<码>/ 三件套 + 出图清单.md
reverse/              逆向中间产物（二值图、裁切块、局部放大）
```

`sources/manifest.csv` 的列值得照抄：`platform, title, url, type, has_dimensions, has_grid, confidence, status, note`。
`has_dimensions` 一列直接决定这份资料能不能当锚点。
